# eval-preflight

A pre-flight check for eval results. It catches partial runs, failed judges, mislabelled scores and
inconsistent aggregation, so the number you gate on is the number your eval actually produced.

**Status: alpha, pre-release (0.0.2). Not published to PyPI.** The full README arrives with 0.1.0;
[SPEC.md](SPEC.md) is the contract.

## What works today

- Inputs ([docs/input-format.md](docs/input-format.md)): the generic format (JSON or JSONL) and
  pydantic-evals reports serialized to JSON. The pydantic-evals adapter is tested against reports
  generated by the real library (`make fixtures`, pydantic-evals 2.61.0).
- Seven checks ([docs/checks.md](docs/checks.md)): `task-failures`, `evaluator-coverage`,
  `evaluator-errors`, `name-collision`, `aggregation-consistency`, `constant-output`, and
  `baseline-comparability` with `--baseline`.
- `eval-preflight check RESULTS`: exit `0` on PASS or WARN, `1` on FAIL, `2` on a usage error.
- Python: `check(load(path))`, or `check_pydantic_evals(report)` for an in-memory pydantic-evals
  report (optional extra `eval-preflight[pydantic-evals]`, which adds the reported averages).

```console
$ uv run eval-preflight check tests/fixtures/pydantic_evals/name_shift.json
```
