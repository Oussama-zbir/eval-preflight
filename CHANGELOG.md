# Changelog

All notable changes to this project are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- promptfoo adapter (`--format promptfoo`, auto-detected) for `promptfoo eval -o results.json`
  exports. Judge failures (`metadata.graderError`), which promptfoo counts as failed assertions,
  become evaluator errors; provider errors (`failureReason` 2) become task errors. An export with
  several prompts or providers is rejected. Tested against exports generated by running promptfoo
  0.125.1 (`scripts/make_promptfoo_fixtures.py`, `make promptfoo-fixtures`).

## [0.1.0] — 2026-11-07

First release on PyPI. The data model (SPEC §5) is frozen from this version.

### Added
- `.github/workflows/publish.yml`: publishes to PyPI with trusted publishing, only when a `v*`
  tag is pushed, after `make check`, `twine check` and a clean-install smoke test, and only if
  the tag matches the package version.
- `scripts/smoke_dist.sh`, run by CI on every push: installs the built wheel in a fresh
  virtualenv outside the checkout and runs the CLI and Python quickstart against it.
- Package metadata: project URLs and supported Python versions.
- CI job `upstream`: installs the newest pydantic-evals 2.x (the extra allows `>=2.61,<3`, the
  fixtures are pinned to 2.61.0), runs the suite against the committed fixtures and regenerates
  them, failing on any byte change. CI also runs weekly and on demand to catch upstream drift.
  First result: pydantic-evals 2.66.0 writes byte-identical fixtures.

### Changed
- `EvalRun` rejects two measurements with the same evaluator id in one case-run, and one evaluator
  id with conflicting `kind`s across the run (SPEC §15, amendment 4). `load()` raises `LoadError`
  and the CLI exits 2, for results and `--baseline`. Both were accepted silently before: the
  duplicate was pooled like a repeat, and a mixed-kind id raised no finding. pydantic-evals
  reports can hit both (two evaluators with the same spec; an evaluator whose return type varies
  by case).
- The version is defined once, in `eval_preflight.__version__`; `pyproject.toml` reads it.
- The sdist no longer includes `.github/` or `CLAUDE.md`.
- README rewritten for the 0.1.0 release: the problem, install, CLI/Python/CI quickstart, the
  checks table, supported inputs, relation to `evaltrust` and `limen-eval`, and limitations.

### Fixed
- JSON nested too deeply for the parser raised an uncaught `RecursionError` (traceback, exit 1,
  which reads as a FAIL verdict). `load()` now raises `LoadError` and the CLI exits 2.

## [0.0.3] — not published

Milestone 3.

### Added
- Check 7, `baseline-comparability` (`--baseline BASELINE`, `--require-same-cases`): WARN when
  cases or evaluators differ from the baseline (FAIL with `--require-same-cases`), FAIL when an
  evaluator's coverage dropped, WARN when repeat counts differ. Python: `check(run,
  baseline=...)` and `check_pydantic_evals(report, baseline=...)`.
- Golden scenario E (baseline), generated from pydantic-evals 2.61.0 with scenario D as baseline.
- `examples/github-action.yml`, run by this repo's CI against the clean-run fixture (must pass)
  and the partial-coverage fixture (must fail) via `scripts/run_action_example.py`.
- `docs/ci.md`: exit codes, flags, baseline gating and the JSON report.
- `--json`: only a machine-readable report on stdout, `{"verdict", "run", "findings"}`; usage
  errors still go to stderr with stdout empty. Python: `CheckResult.to_json()`.

## [0.0.2] — not published

Milestone 2.

### Changed
- Python floor raised to 3.11; CI runs 3.11, 3.12 and 3.13.
- pydantic-evals evaluator ids use the approved `Name(key=repr(value), ...)` form with sorted keys
  (was JSON-encoded). pydantic-evals' compact one-element arguments carry no field name, so they
  render positionally: `Judge('strict')`.

### Added
- In-memory pydantic-evals path: `check_pydantic_evals(report)` and `from_pydantic_evals(report)`,
  behind the optional extra `eval-preflight[pydantic-evals]`. Adds `reported_aggregates` from
  `report.averages()` and `source_version`; the JSON path still works without the extra.
- Multi-output pydantic-evals evaluators: each named output gets its own id,
  `Name(...)[output]`.
- Golden scenario C (repeat divergence), generated from pydantic-evals 2.61.0.
- Check 6, `constant-output`: WARN when a score or label evaluator returns one value on every
  case-run where it produced one, over at least `--min-cases-for-constant` (5) case-runs.
  Assertions are exempt.
- Non-finite values (NaN, ±inf) no longer count as coverage: `evaluator-coverage` adds a FAIL
  "non-finite value" finding, and `aggregation-consistency` excludes them from both estimators.
- Check 5, `aggregation-consistency`: compares the pooled mean with the mean of per-case means
  per evaluator and for all assertions, and verifies that each reported aggregate is reproducible
  from the raw results (stating which estimator and from how many cases). New flags
  `--aggregation-tolerance` and `--strict-aggregation`.
- pydantic-evals adapter for JSON reports (`--format pydantic-evals`, auto-detected). Evaluator
  identity comes from each result's `source`, never from the display key; results without a
  source are rejected as unverifiable.
- `scripts/make_fixtures.py` (`make fixtures`): generates the golden fixtures for scenarios A, B
  and D by running pydantic-evals 2.61.0; the golden tests run on both the generic and the
  generated fixtures.

## [0.0.1] — not published

### Added
- Canonical data model (`EvalRun`, `CaseResult`, `Measurement`, `EvaluatorRef`); duplicate
  case-runs are rejected.
- Generic input adapter (JSON document or JSONL) with format auto-detection.
- Checks: `task-failures`, `evaluator-coverage`, `evaluator-errors`, `name-collision`.
- `eval-preflight check` CLI with `--format`, the three rate thresholds, `--warnings-as-errors`
  and `--quiet`; exit codes 0 (PASS/WARN), 1 (FAIL), 2 (usage error).
- Python API: `load`, `check`, `CheckResult.verdict`, `.findings`, `.raise_if_failed()`.
- Hand-written generic fixtures for golden scenarios A, B and D.
